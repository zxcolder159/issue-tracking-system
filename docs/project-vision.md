# Project Vision — Issue Tracking System

Веб-система управления задачами в духе Jira / YouTrack / Kaiten. Система состоит из изолированных пространств: у каждого свои участники, роли и настраиваемый рабочий процесс. Цель — не «список задач с полями», а инструмент, в котором команда сначала описывает свой процесс, а система помогает ему следовать.

## Ключевая идея

Центральная сущность системы — не issue, а lifecycle: граф статусов и разрешённых переходов. Board — представление этого графа. Столбец — статус, перенос карточки — не «изменение поля», а переход по ребру, который система разрешает по правилам или внятно отклоняет. Поэтому настройка столбцов и правил переходов — ядро продукта, а не второстепенная функция.

## Принципы

- Пространство — отдельный мир. Свой набор пользователей и ролей: один человек может быть Project Lead в одном проекте и Developer в другом. Права проверяются в контексте пространства, а не глобально.
- Права понятны и предсказуемы. Developer редактирует только свои issues, Project Lead — любые. Любой запрет объясняется, молчаливых ошибок нет.
- Данные не теряются молча. Удаление — всегда soft delete: корзина на 7 дней с возможностью восстановления.
- Минимум трения. Основной режим — Board: карточки, drag-n-drop, date picker, всё важное видно без открытия карточки. List view — для обзора бэклога и массовых операций.

## Критерии успеха Stage 1

Команда из нескольких человек создаёт пространство, добавляет участников с ролями, настраивает собственные статусы и правила переходов, заводит бэклог и ведёт его на доске. Система корректно запрещает неразрешённые переходы и правки вне полномочий роли, удалённые issues восстанавливаются из корзины. Всё работает стабильно, без ручных правок данных.

## Не-цели Stage 1

Комментарии, история изменений, уведомления, дашборды и интеграции отложены (часть уточняется у заказчика). Приоритет Stage 1 — законченный и надёжный функционал, а не набор полуготовых функций.

## Развитие

Комментарии и история изменений → поиск и фильтры → метрики по пространству (узкие места lifecycle, просрочки) → API и интеграции. Граф lifecycle — основа для будущих отчётов, SLA-правил и автоматизаций.
